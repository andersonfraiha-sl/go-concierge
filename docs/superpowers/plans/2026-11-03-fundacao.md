# Fundação Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tirar toda a persistência do concierge de arquivos JSON para o Postgres 18, atender todas as administradoras num processo só (ou uma, por configuração), e proteger toda rota `/api/*` com papéis em herança e escopo.

**Architecture:** Núcleo puro + bordas. Cada área (mapeamento, memória, pedidos, sessões, acesso) tem tipos e regras puras no seu pacote, uma interface de armazenamento pequena e duas implementações: Postgres (ent por padrão, sqlc só nas duas exceções de desempenho) e um fake em memória para teste unitário. Um teste de contrato roda o mesmo cenário contra as duas. Multi-administradora entra antes dos stores Postgres, para o esquema já nascer com `administradora_id`.

**Tech Stack:** Go 1.27, Postgres 18, ent v0.14.6, Atlas v1.3.0, pgx v5.12.0, goose v3.29.0 (biblioteca, migrations embutidas), sqlc v1.31.1, testcontainers-go v0.44.0, Eino v0.9.22.

**Spec:** `docs/superpowers/specs/2026-11-03-fundacao-design.md` · Constituição: `docs/superpowers/constitution.md` · Gate: `docs/superpowers/gates/2026-11-03-fundacao-spec-gate.md`

## Global Constraints

- Versões exatas da tabela "Versões" da spec (§3). Nada abaixo delas.
- **ent é o acesso padrão.** Esquema em `internal/banco/ent/schema/*.go`, código gerado em `internal/banco/ent` (`go generate ./internal/banco/ent`, nunca editado à mão). Entidade do ent nunca sai do pacote do store: o store converte para o tipo de domínio.
- **sqlc só nas exceções listadas** (Tasks 6 e 7). Queries em `internal/banco/queries/*.sql`, código em `internal/banco/sqlc`; cada query começa com `-- por que não ent: <motivo>`. Nenhum SQL em string fora do sqlc e das migrations.
- **Migrations**: o esquema do ent é a fonte; `go run ./internal/banco/cmd/gerar-migration <nome>` usa o Atlas (`migrate.NamedDiff` com `sqltool.NewGooseDir`) contra um Postgres 18 descartável (testcontainers) e escreve `internal/banco/migrations/NNNN_<nome>.sql` no formato goose. Migration gerada é commitada e revisada; ajuste manual só para dados (ex.: papéis iniciais), em migration separada.
- Nenhuma persistência em arquivo ao fim do plano (constituição II). Arquivo só como fonte do `importar-json`.
- Erros: `fmt.Errorf("<operação> <alvo>: %w", ...)`, sem "failed to"; sentinelas por pacote; nunca `_ = err`, `return nil, nil` em falha ou `continue` silencioso.
- Toda chamada ao banco recebe o `ctx` da requisição; o pool abre com `ConnectTimeout` de 5s; toda query de requisição HTTP roda com `context.WithTimeout(ctx, 3*time.Second)`.
- Logs `log/slog` JSON com `request_id`, `usuario_id`, `operacao`, `duracao_ms`. Telefone só mascarado (`5519****2710`), nunca CPF nem texto de mensagem.
- Funções de regra são puras e testadas em tabela; I/O só em `Postgres*`, handlers e `main`.
- Nomes: "papel de acesso" (RBAC) ≠ "papel do morador" (`Habilitacao.Papeis`, inalterado).
- Commit ao fim de cada tarefa, mensagem `type(scope): descrição em minúscula` (sem Jira: `feat: ...`, `refactor: ...`). Push só quando o Felipe confirmar o remoto (o repo é do Anderson).

## Review Focus

1. **Mesmo telefone em formatos diferentes** (`+55 (19) 94040-2710`, `5519940402710`) tem que cair na mesma memória e carteira. → teste na Task 5.
2. **Duas mensagens simultâneas do mesmo contato** não podem perder escrita de memória ou pedido. → teste concorrente nas Tasks 6 e 7.
3. **Restart com sessão em `Processando=true`**: ao recarregar, a sessão volta destravada, senão o contato fica mudo para sempre. → teste na Task 8.
4. **Condomínio que muda de administradora** depois de ter conversas: os registros antigos continuam com a administradora gravada e só ela os vê. → teste na Task 10.
5. **`importar-json` rodado duas vezes** não duplica nada e a contagem bate. → teste na Task 12.
