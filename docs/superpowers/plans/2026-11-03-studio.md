# Studio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Um app só, "Studio" (React em `studio/`, servido embutido em `/studio`), que substitui Backdoor e Admin, com vocabulário comum, fluxo de cada skill em blocos editáveis, salvamento automático e telas que dependem das permissões do usuário.

**Architecture:** O backend Go ganha um núcleo puro em `internal/okf` (caso.yaml ↔ blocos, validação "Gravar precisa de Confirmar", geração do `workflows/principal.md`), uma camada fina no `Catalogo` que lê e grava os arquivos com checagem de versão, e handlers novos em `cmd/okf-admin/studio.go` (`/api/eu`, `/api/skills/...`). O front é um SPA Vite com MUI, React Flow para o fluxo em coluna e TanStack Query; toda resposta da API passa por Zod na borda. Os endpoints antigos (`/api/agente`, `/api/arquivo`, `/api/admin/*`, `/api/nexus/*`) continuam e são consumidos pelo Studio onde já servem.

**Tech Stack:** Go 1.27 (net/http, gopkg.in/yaml.v3), React 19.3, Vite 8.3, MUI 9.5, @xyflow/react 12.12, TanStack Query 5, React Router 8, Zod 4, Vitest 5 + Testing Library + jsdom, TypeScript 7.

**Spec:** `docs/superpowers/specs/2026-11-03-studio-design.md` · Constituição: `docs/superpowers/constitution.md`

## Review Focus

1. **Ferramenta fora do catálogo** (MCP fora do ar, nome digitado errado): o bloco continua aparecendo, é classificado pelo verbo do nome (`get-`, `list-`, `fetch-`… = Buscar; o resto = Gravar) e mostra um aviso; nunca vira "Buscar" por omissão. → teste na Task 2 (`TestClassificarFerramenta`) e na Task 11 (`showsUnknownToolWarning`).
2. **Edição durante uma gravação em voo, ou saída da página antes do 1 s**: a edição sai numa segunda gravação; sair da página grava o que falta. → Task 8 (`savesEditMadeDuringFlightAfterFirstSave`, `flushesPendingEditOnUnmount`).
3. **Duas pessoas na mesma skill**: a segunda gravação recebe 409 e a tela diz "Esta skill mudou desde que você abriu. Recarregue para continuar." sem descartar o que está na tela. → Task 4 (`TestSalvarFluxoRecusaVersaoAntiga`) e Task 11 (`showsConflictAndKeepsEdit`).
4. **Skill sem fluxo** (`faq`, `regimento`): a aba Fluxo explica e não quebra; o servidor responde 404 `SEM_FLUXO`. → Task 5 (`TestStudioAPI` caso `fluxo de skill sem fluxo`) e Task 11 (`showsNoFlowMessage`).
5. **Tela abaixo de 900 px**: construtor também só lê (sem "+", sem arrastar, painel desabilitado). → Task 7 (`narrowScreenDisablesEditing`) e Task 11 (`narrowScreenIsReadOnly`).

- Mapeamento (o mesmo em `AplicarFluxo`, na ordem de escrita das chaves; `Extra` vem depois, chaves em ordem alfabética; string vazia não é escrita):

  | YAML | `Tipo` | Campos do `Bloco` |
  |---|---|---|
  | `resource: R`, `with`, `save_as`, demais chaves do passo → `Extra` | `escrita(R)` ? `gravar_no_sistema` : `buscar_dados` | `Recurso`, `Com` (ordem do `with` preservada), `GuardarEm` |
  | `choose: {param, title, from, label, value, ask, empty, reuse, …→Extra}` | `pedir_escolha` | `Param`, `Titulo`, `De`, `Rotulo`, `Valor`, `Pergunta`, `SeVazio`, `Reaproveitar` |
  | `collect: X` (string ou lista) | `perguntar` | `Campos` (sempre escrito como lista) |
  | `form: {fields_from, save_as, …→Extra}` | `formulario` | `De`, `GuardarEm` |
  | `confirm: T` | `confirmar` | `Texto` |
  | `compose: T` | `montar_texto` | `Texto` |
  | `reuse: {slot \| slots, confirm, from, label, value, ask, …→Extra}` | `reaproveitar` | `Campos` (escreve `slot` se 1, `slots` se mais), `Confirmacao`, `De`, `Rotulo`, `Valor`, `Pergunta` |
  | `output: T` (raiz) | `responder`, sempre o último bloco | `Texto` |
  | `params[i]`: `name, title, ask, type, options`, resto → `Extra` | — | `Informacao` (`options` de mapas `{value,label}` → `Opcoes`; lista de strings → `Opcoes` com valor = rótulo e `OpcoesSimples=true`) |

## Decisões tomadas sobre ambiguidades da spec

- O passo `reuse` existe em três `caso.yaml` e não está na tabela da spec: virou o bloco "Reaproveitar resposta", cor de perguntar `#7B1FA2`.
- Leitura × escrita de `resource` vem do catálogo (`Recurso.Write`); fora dele, do verbo do nome (mesma regra do MCP) com aviso no bloco. O cliente nunca decide: o servidor reclassifica antes de validar.
- "Gravar sem Confirmar antes" = cada Gravar precisa de um Confirmar depois da gravação anterior (um sim não vale para duas gravações).
- "Mesmo conteúdo" na ida e volta é semântico: `collect: x` volta como `collect: [x]`; comentários dentro de `steps`/`params` se perdem, o resto do arquivo fica. A ordem do `with` é preservada (a redação do `.md` depende dela).
- `principal.md` só é gerado para skill com `caso.yaml`; os de `faq`, `regimento`, `observador-sessao` e do Assistente continuam à mão (Avançado › Arquivos). Os quatro `.md` hoje fora de dia com o `caso.yaml` são regerados.
- "Quando usar" = `description` do `caso.yaml`, copiado para `agent.yaml descricao` e para a linha da rota no pai; palavras-chave entram na mesma aba.
- Textos e fluxo são globais (catálogo em arquivo): editar exige a permissão e escopo Superlógica (`administradoraId` nulo). O gestor, mesmo com `skills.editar_textos` da Fundação, só lê a skill; ele edita orientações e habilitação do condomínio dele.
- `/api/eu` lista também `condominios.editar` e `administradoras.editar` (da Fundação), que a spec não cita, para as seções de Identificação e Administradoras.
- Conflito entre duas edições: versão por parte (fluxo e textos separados, hash do conteúdo) e 409; sem mescla automática.
- Mover skill para outro pai some (o Studio tem lista plana); clonar virou "Duplicar".
- Matriz skills × condomínios do Admin não foi portada; a mesma decisão é feita no detalhe de cada condomínio e no "Padrão (todos)".
- Skill nova nasce com um Montar texto e um Responder ("Pronto! Em que mais posso ajudar?"), porque um `caso.yaml` sem passos é inválido.
